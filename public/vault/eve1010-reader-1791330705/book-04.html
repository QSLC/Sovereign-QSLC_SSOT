Expanded Chapter 9 — The Formula Provenance Graph

A flat formula table is not enough for a living system. The next architecture is a formula provenance graph. Each formula node stores its version, name, expression, units, class, source, assumptions, dependencies, test cases, output destinations, and retirement status. Edges show which formulas depend on which inputs and which dashboards consume the results.

This structure solves three problems. First, it prevents identifier collision: F-12 can have versioned meanings instead of one ambiguous label. Second, it enables replay: the system can reconstruct what a result meant on a specific date. Third, it separates evidence classes. A standard physics expression can point to an external scientific source while a project model points to the internal specification that introduced it.

The graph is also a better patent-support artifact than a marketing screenshot because it documents the concrete flow of information. It can show how data enters, how transformations occur, how validation gates are applied, and how output actions are constrained. It does not prove patentability by itself, but it creates disciplined technical evidence.

Expanded Chapter 10 — What Can Be Protected and What Must Stay Honest

The strongest intellectual-property strategy starts by refusing to claim ownership over things the project did not create. Established physics remains established physics. Generic encryption remains generic encryption. Common database, event, and automation patterns remain common building blocks.

The protectable center, if it proves novel and non-obvious, is more likely to be a specific implementation: the arrangement of a natural-language command bus, versioned formula provenance, evidence-gated state transitions, local-first recovery, synthetic public twins, and an auditable SSOT. Copyright protects the text, diagrams, and code expression. Trade-secret practices can protect unpublished weights, configuration, customer data, and implementation details. Trademarks can protect source-identifying names. Patent counsel can evaluate whether a concrete technical process meets the legal requirements for a patent.

This is why the public books reveal enough to teach the method without dumping secrets that do not need to be public. A reader should understand the architecture. A competitor should not receive a free copy of every private credential, weight, rule, or production dataset.
